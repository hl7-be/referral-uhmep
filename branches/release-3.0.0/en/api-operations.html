This page is a compact operational map of the eReferral API. It is intended as an implementation checklist, not a replacement for the generated FHIR profiles or the eHealth API Portal contract.

Operations are grouped by business objective so an integrator can start from the workflow they need to implement and then identify the FHIR interaction, resource profile, and important rules.

The errors for these operations are maintained in the eReferral API Error Codes workbook. Each detailed operation page links to the workbook and the Error Codes usage guidance.

Search Filters

Search filters are submitted as application/x-www-form-urlencoded key-value pairs in POST /ServiceRequest/_search.

Filter Purpose Status
patient Filter by patient pseudonym in transit for the eReferral domain. Active
status Filter by FHIR ServiceRequest.status; translate from business status first. Active
statusReason Filter by additional prescription status information. Active
_has:Task:focus:status with _profile Filter by summary execution/referral-task status. Active
requester Filter by prescriber. Organization-scoped requester references use PractitionerRole/{SSIN}-{DISCIPLINE}-NIHII-{nihii11Organization}. Active
_has:Task:focus:owner Filter by assigned caregiver or assigned organization. Active
code Filter by template code using {system}|{code}. To be replaced by category with system=https://www.ehealth.fgov.be/standards/fhir/terminology/CodeSystem/be-cs-prescription-type
intent Separate prescriptions (order) from proposals (proposal). Active
_count Page size. Default and maximum are currently 25. Higher values return an invalid-count error. Active
_offset Zero-based result offset. Defaults to 0. Active

Unassign a Care Provider

Business objective Actors Endpoint Task profile Success Key integration notes
Remove an assignment Patient
Caregiver
Organization		 DELETE /Task/{executionID} BePerformerTask or BeOrganizationTask 204 No Content - For ambulatory radiology, allowed while the prescription is READY or IN_PROGRESS and the execution task is ready or in-progress; the prescription returns to READY.

Manage Execution Progress

Healthcare professionals and organizations do not update the clinical ServiceRequest to record execution. They create or patch task resources.

Record Execution Start

Business objective Actors Endpoint Task status after operation Success Key integration notes
Start execution, not assigned yet - Healthcare Professional
- Organization		 POST /Task in-progress 201 Created - Create a task with only executionPeriod.start.
- Start date must not be in the future.
- If execution is performed by an internal professional, the organization must link the performer task to the organization task with basedOn.
Start execution, already assigned - Healthcare Professional
- Organization		 PATCH /Task/{executionID} in-progress 200 OK - Add Task.executionPeriod.start.
- Previous task status must be ready or cancelled.

Record Execution End

Business objective Actors Endpoint Task status after operation Success Key integration notes
Finish execution, not assigned yet - Healthcare Professional
- Organization		 POST /Task completed 201 Created Create a completed task with:
-executionPeriod.start
-executionPeriod.end
Finish execution, already started - Healthcare Professional
- Organization		 PATCH /Task/{executionID} completed 200 OK - Add only Task.executionPeriod.end.
- End must not be in the future.
- End must not be before start.
- Radiology on the urgency track may finish while the prescription is still in business state READY.

Record Execution Interruption

Business objective Actors Endpoint Task status after operation Success Key integration notes
Interrupt execution Healthcare Professional PATCH /Task/{executionID} on-hold 200 OK - Replace Task.status.
- No informed-consent, therapeutic-relation, or exclusion checks are applied for this interruption operation.

Cancel Execution

Business objective Actors Endpoint Task status after operation Success Key integration notes
Cancel execution Healthcare Professional
Organization		 PATCH /Task/{executionID} cancelled 200 OK - Replace Task.status by cancelled.
- The task can later be reused by the caregiver.

Manage Evaluation

Evaluate Proposal

Business objective Actors Endpoint Success Notes
Approve proposal Healthcare Professional (Physician) POST /ServiceRequest/{serviceRequestID}/$approve 200 OK - Completes the proposal workflow.
- Creates a valid prescription.
- Assigns the caregiver who authored the proposal.
- Optional clinical note must be encrypted.
Reject proposal Healthcare Professional (Physician) POST /ServiceRequest/{serviceRequestID}/$reject 200 OK - Completes the proposal workflow as rejected.
- Optional clinical note must be encrypted.
