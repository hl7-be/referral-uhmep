Radiology terminology

Artifact Source Used for Binding / mapping notes
be-vs-prescription-type eHealth branch build Diagnostic imaging prescription type in ServiceRequest.category[prescriptionType]. Use with be-cs-prescription-type#diagnostic-imaging-appendix-82.
be-vs-diagnostic-imaging-procedure Local eReferral IG SNOMED CT diagnostic imaging procedure in ServiceRequest.code. Prefer the local eReferral artifact because it is defined in this IG.
be-vs-diagnostic-imaging-condition Local eReferral IG SNOMED CT body structure, disorder, finding, situation, or staging condition supporting the imaging request. Prefer the local eReferral artifact because it is defined in this IG.
be-cs-pss-qsi-indications / be-vs-pss-qsi-indication Local eReferral IG PSS/QSI indication codes for diagnostic imaging requests. Prefer the local eReferral CodeSystem/ValueSet because the PSS indication content is bundled in this IG.
ereferral-vs-imaging-patient-condition-indication Local eReferral IG Combined patient-condition indication binding for diagnostic imaging supporting information. Includes local PSS/QSI indications and local SNOMED CT diagnostic imaging conditions.
be-cs-radiology-supporting-info-role / be-vs-radiology-supporting-info-role Local eReferral IG Role of each radiology supportingInfo item. Codes include prior-results, prior-request, attention-condition, safety-checklist, and patient-condition.
be-cs-request-track / be-vs-request-track eHealth branch build Care setting / request track such as ambulatory. Used in ServiceRequest.orderDetail.
be-cs-imaging-modality / be-vs-imaging-modality eHealth branch build Imaging modality types for prior imaging requests. Use the branch build until the artifact is available in a stable official publication or duplicated locally.
be-cs-imaging-priority / be-vs-imaging-priority eHealth branch build Imaging-specific priority codes. The base FHIR RequestPriority binding may still apply where the profile uses ServiceRequest.priority.
be-vs-implant-type eHealth branch build Implant information captured in the imaging attention-conditions response. Used by the supporting questionnaire/response content rather than directly by the main ServiceRequest.code.
